Weekly Prompt in ReadME

  The question I will be answering is, "Explain what the term “full coverage” means with respect to tests, and why it may or may not be a reasonable goal for some projects." the term full coverage referring to formulating tests for your program that account for all possible cases of expected and unexpected inputs that maybe provide by a user. The aim of such a test is to see how a program will function when used as expected as well as when it is used in unexpected way. Doing these kinds of test allow a programming to find potential issues before they become a problem for the user and have a fix or work around in place. While this concept is good in theory, in practicality it is a high bar to test for all possible edge cases, as every person is unique and as such how they choose to interact with your program, is completely unknown, so having a program that can pass such a test while it is need to for important software used by many on a day to day basis to prevent widespread issues, amongst users. However for something like a fishing game, that you put up on your GitHub as your learning to code, testing for and making your code robust against all invalid input would likely take more time that simple making the program function, as in its simplisty and lack widespread user or a userbase have a few issue from usually input hurts no but the creator, and the need for thinking up all possible edge cases is simply more effort than it is worth.
